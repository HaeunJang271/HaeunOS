# M25.1 Memory Architecture Audit

Date: 2026-11-16  
Scope: **READ-ONLY**. No source or ABI changes.

Two guest kernels exist in-tree; this audit centers on the **process-v1 + host `app_env`** path used by desktop/apps (M14–M24). The separate foundation `kernel/mm` (PMM/heap) is noted where relevant and is **not** wired into process-v1 SPAWN/FORK.

---

## 1. Guest physical memory

| Item | Value | Evidence |
|------|-------|----------|
| Host-allocated guest RAM | **256 MiB** (`calloc`) | `src/main.c` `INITIAL_RAM_SIZE` |
| VM binding | `haeun_vm_init_version(..., ram, INITIAL_RAM_SIZE, ...)` | `main.c` |
| Bootinfo `ram_size` / `stack_top` | 256 MiB | `main.c` |
| Page size | 4 KiB | `docs/mmu-v1.md`, `src/mmu.c` / `src/pt.c` |

Process-v1 **uses a small fixed region** of that RAM (page tables, PCB, code slots, stacks, window pool, FB). Most of the 256 MiB is unused by the current process memory manager.

---

## 2. Address space (AS) creation

| Mechanism | Behavior | Location |
|-----------|----------|----------|
| Boot maps 3 AS | `map_slot0/1/2` build L1/L0 | `kernel/process/proc_boot.s` |
| AS count | `HAEUN_APP_SLOTS` / `HAEUN_GUEST_PCB_AS_SLOTS` = **3** | `include/haeun/app_env.h`, `guest_pcb.h` |
| PCB rows | `NPROC=4`; FORK scans slots **0..2 only** | `proc_fork.s` comment + cap |
| Switch | `switch_as`: `CSR ptbr` ← PCB.`ptbr`, `SFENCE` | `proc_sched.s` |

AS are **static templates**, not dynamically allocated page-table heaps.

---

## 3. AS ranges and ownership

### Page-table roots (PA)

| Slot | L1 | L0 | `ptbr` (MODE\|PPN) |
|-----:|----|----|---------------------|
| 0 | `0x2000` | `0x3000` | `0x00002001` |
| 1 | `0x6000` | `0x7000` | `0x00006001` |
| 2 | `0x8000` | `0x9000` | `0x00008001` |

Constants mirrored in `src/app_env.c` (`k_l0`, `k_ptbr`) and `proc_boot.s` / `proc_fork.s` `fork_stacks`.

### Per-slot user code / stacks (PA)

| Slot | Code PA | UStack page | UStack top | KStack top |
|-----:|---------|-------------|------------|------------|
| 0 | `0x00108000` | `0x00113000` | `0x00114000` | `0x00124000` |
| 1 | `0x0010C000` | `0x00114000` | `0x00115000` | `0x00125000` |
| 2 | `0x0010D000` | `0x00115000` | `0x00116000` | `0x00126000` |

- **User VA for app code (all slots):** `0x00108000` (`HAEUN_APP_USER_VA`), ≤4 KiB.  
- **User stack VA:** identity-style per slot (`0x113000` / `0x114000` / `0x115000` pages).  
- **Ownership:** process owning the PCB that holds that slot’s `ptbr`; host tracks SPAWN via `haeun_app_env.runs[slot].pid`.

### Shared / global (not per-process exclusive)

| Region | Role |
|--------|------|
| `0xA000` PCB bank | All processes’ PCBs |
| Kernel text `0x00100000+` | Mapped into each AS without `U` (`fill_k`) |
| MMIO window via L0 @ `0x4000` | IRQC/timer/UART PTEs |
| Window backing pool `[0x18000, 0x100000)` | Guest-chosen PA; `owner_pid` on WM |
| Primary FB (e.g. `0x00200000`) | Compose target |

## 4. Process image layout (code / data / stack / heap)

| Segment | process-v1 reality |
|---------|-------------------|
| Code | Single user page VA `0x108000` → slot code PA; PTE `0x1b` = V\|R\|X\|U (**no W**) |
| Data | No separate data segment; apps are typically position-dependent asm in the code page |
| Stack | One 4 KiB user page per AS; PCB `ustack_base` / `ustack_top` / saved `r13` |
| Heap | **No guest heap allocator** on process-v1 path (no `brk`/`malloc` syscall) |

Foundation-only: `kernel/mm/heap.c` bump heap + `pmm_*` for firmware/`kmain` path — **not** used by `APP_SPAWN` / desktop.

---

## 5. SPAWN memory initialization

Entry: `haeun_app_spawn` (`src/app_env.c`).

1. Validate HXF (`extract_user` / `haeun_sec_validate_exec`) **before** mutate.  
2. Orphan ZOMBIE PCB memset on unused slots.  
3. Find FREE PCB + unused `runs[slot]` (slots 1–2).  
4. `memset` code PA + ustack page; `memcpy` image ≤4 KiB.  
5. Write L0 user-code PTE → `k_code_pa[slot] | 0x1b`; `haeun_tlb_flush`.  
6. Fill PCB: READY, pid, ppid, epc=`USER_VA`, ptbr/stacks/fd0.

Failure before step 4 leaves no partial code write (validated first).

---

## 6. FORK memory behavior

Entry: `sys_fork` / `fork_stacks` (`proc_fork.s`).

| Copied | Not copied |
|--------|------------|
| New PCB fields, GPRs, pid/ppid, epc | User code page contents |
| Per-slot `ptbr` + stack pointer fields | Page-table rebuild |
| Child fd0=console | COW / shared frame accounting |

**Actual model:** PCB+context fork onto a **prebuilt AS slot**, not a memory image clone. Child executes at parent’s `epc` VA under **child’s** page tables.

---

## 7. EXIT / fault memory reclaim

| Stage | Action | Code |
|-------|--------|------|
| Host | `reap_pid` → `haeun_app_reap` → `scrub_slot` (slots **1–2** only) | `ecall_mux.c`, `app_env.c` |
| Scrub | Zero code PA, zero ustack page, clear user-code PTE, TLB flush | `scrub_slot` |
| Guest | PCB → ZOMBIE; `orphan_reparent` | `proc_sys.s` |
| PCB FREE | WAIT / TRYWAIT / SPAWN orphan memset | `proc_fork.s`, `app_env.c` |

Slot 0 (desktop) is **not** scrubbed by `scrub_slot` (`slot < 1` guard).

---

## 8. ZOMBIE → FREE and memory

| Event | Memory pages | PCB |
|-------|--------------|-----|
| EXIT/fault | Host scrub already done (SPAWN apps) | ZOMBIE |
| WAIT/TRYWAIT | No further page wipe | FREE + fd clear |
| SPAWN memset orphan | PCB zero only (pages already scrubbed if reap ran) | FREE |

Pure FORK children may never hit `haeun_app_reap` (no `runs[]`); their code PTE/stack pages are **not** scrubbed by host reap unless SPAWN later reuses the slot.

---

## 9. PCB ↔ AS link

| PCB field | Meaning |
|-----------|---------|
| `ptbr` (+28) | Root for `switch_as` |
| `kstack_top` / `ustack_*` | Trap/user stacks for that slot |
| Slot index | Implicit: PCB index 0..2 ↔ AS 0..2 (FORK/`APP_SPAWN`) |

`haeun_guest_pcb_current_pid()` reads current PCB (`src/guest_pcb.c`).

---

## 10. Host VM memory vs guest memory

| Layer | What |
|-------|------|
| Host process | C heap (`malloc` for image load, viewer BGRA); **not** guest objects |
| Guest RAM buffer | One contiguous `uint8_t *ram` of 256 MiB owned by the VM |
| Guest VA | Translated via guest page tables when `ptbr.MODE=1` (`src/mmu.c`) |
| Host assists | Read/write guest RAM by PA/VA helpers; ownership checks for windows/fds |

Host does not provide a general guest page allocator API for process-v1 beyond fixed slots + scrub.
