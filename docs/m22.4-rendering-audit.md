## Findings

### R1 — Dual present path (info / by design)

| Field | Value |
|-------|--------|
| Repro | Idle with `--viewer` vs `--fb-dump` only |
| Expected | Single coherent FB |
| Actual | Guest `GFX_COMPOSE` (ECALL 23) **and** viewer `haeun_gfx_chrome_present` each slice |
| Sources | `userland/desktop_draw.s` `shell_compose`; `src/vm_viewer_blit.c`; `src/gfx_chrome.c` |
| Cause confirmed | Yes — intentional (viewer authoritative under `--viewer`) |
| Severity | **Info** — documented M22.2; no defect found in PPM path |

### R2 — Host chrome vs PPM (info)

| Field | Value |
|-------|--------|
| Repro | Open calc under `--viewer` vs PPM dump without viewer |
| Expected | Same decorations |
| Actual | Host title bar / borders drawn only in `paint_one` during `chrome_present`; pure guest compose PPM lacks those chrome pixels |
| Sources | `gfx_chrome.c` `paint_one` |
| Cause confirmed | Yes |
| Severity | **Info** — PPM ≠ live viewer chrome; not a guest layout bug |

## Conclusion

No confirmed rendering defect requiring a guest/host graphics change. Layout stays inside 320×180; tiles do not duplicate; life-cycle restores shell. Remaining gaps are **viewer-vs-PPM chrome**, **dual compose ownership (intentional)**, and **physical HID (manual)**.
