# M25.5 Memory Layout Audit (READ-ONLY)

Date: 2026-11-16  
Scope: process-v1 as implemented. Values below are from cited sources only.  
**No heap exists today.**

## 1. Guest RAM

| Item | Value | Source |
|------|-------|--------|
| Host VM RAM size | `256 MiB` (`256 * 1024 * 1024`) | `src/main.c` `INITIAL_RAM_SIZE` |
| Firmware stack_base (non-process path) | `0x0FF00000` | `INITIAL_STACK_BASE` |
| Bootinfo VA | `0x0FEFF000` | `BOOTINFO_ADDRESS` |

process-v1 user stacks are **not** the firmware stack; they use the low megabyte maps below.

## 5. M25.4 guard pages

| Slot | Guard VA | PTE policy |
|-----:|----------|------------|
| 0 | `0x112000` | Cleared (`V=0`) at L0 `+0x448` |
| 1 | `0x113000` | Cleared at L0 `+0x44c` |
| 2 | `0x114000` | Kernel RW identity `0x00114007` (no U); user faults |

Must not place user-heap U\|RW on these VAs.

## 6. Kernel / shared maps (per AS via `fill_k` / MMIO)

| Region | VA / notes | Flags (typical) |
|--------|------------|-----------------|
| Kernel text | `0x00100000`..`0x00107000` (8 pages) | RX, no U (`0x0b`) |
| PCB page | `0x0000A000` | RW kernel |
| Foreign code identity | `0x10C000`, `0x10D000` | RW kernel (FORK memcpy) |
| Foreign ustack identity | `0x114000`, `0x115000` (where not overwritten by local U stack) | RW kernel |
| PT pages identity | L1/L0 PAs `0x2000`..`0x9000` | RW kernel |
| MMIO L1 | via `0x4000` non-leaf; devices `0x10000000`+ | device maps |

## 7. PTE capacity

- Sv32: one L0 page = 1024 leaf entries × 4 KiB → 4 MiB window per L1 VPN1.  
- process-v1 uses a **small fixed set** of leaves (code, stack, kernel, identity helpers).  
- Many VPN0 indices in the `0x0010xxxx` band are **unused** (e.g. `0x109`..`0x10B`, `0x10E`..`0x111`) — candidates for a future heap leaf, **if** PA is reserved and guards/stacks untouched.

## 8. SPAWN / FORK address-space init

| Path | Behavior | Source |
|------|----------|--------|
| Boot | `map_slot0/1/2` + `fill_k` / `fill_u` | `proc_boot.s` |
| SPAWN | Wipe code+ustack PA; set code PTE `pa\|0x1b`; PCB stacks from `k_ustack_*` | `haeun_app_spawn` |
| FORK | `fork_stacks` + copy code page + copy ustack + relocate SP; READY after clone | `proc_fork.s`, `proc_fork_mem.s` |

**No heap PTE, PA, or copy** in either path.

## 9. Scrub range

`scrub_slot` (slots ≥1 only): zero **code PA** (4 KiB), zero **ustack PA** (4 KiB), clear **user-code PTE** at L0 `+0x420`.  
Does **not** clear stack PTE or any heap (none). Slot 0 never scrubbed.

## 10. Exit / reclaim

Guest: EXIT/fault → ZOMBIE; WAIT/TRYWAIT frees PCB.  
Host: `haeun_app_reap` / `haeun_ecall_mux_on_fault` → window/IPC reap + `scrub_slot` when mux present.

## Gaps relevant to heap

- No dedicated user RW page besides ustack.  
- Code page is RX — cannot host a writable allocator arena.  
- Free VA/PA holes exist but are **not** owned or scrubbed yet.
