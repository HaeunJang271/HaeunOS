# M25.1 → M25 Memory Management Proposal

Date: 2026-11-16  
Companion: [m25.1-memory-architecture-audit.md](m25.1-memory-architecture-audit.md), [m25.1-memory-safety-audit.md](m25.1-memory-safety-audit.md)

Constraint: preserve HAEUN-32 ISA, process-v1 ABI surface unless a proven defect forces an additive syscall; do not break WM/desktop or M24 lifecycle contracts.

---

## Phase 2 — Structure evaluation

| Structure | Implemented now? | Why it matters | Difficulty | ISA/ABI impact | Priority |
|-----------|------------------|----------------|------------|----------------|----------|
| Static memory allocation (fixed AS slots) | **Yes** (`proc_boot` + `app_env`) | Predictable; matches NPROC/AS=3 | — | None | Keep as base |
| Per-process address space | **Yes** (3 PT roots + `switch_as`) | Isolation backbone | — | None | Keep; harden |
| Memory region manager | **No** (ad-hoc constants) | Single place for code/stack/pool bounds | Medium | None if host/guest tables only | **P1** |
| Heap allocator (guest) | **No** on process-v1 | Apps need dynamic buffers without stealing window PA | Medium–High | Likely new `brk`/`HEAP_*` ECALL | **P2** (after region map) |
| Page allocator (guest PMM) | Foundation `kernel/mm` only; **not** in process-v1 | Needed before many dynamic regions / COW | High | Optional; can stay host-assisted | **P3** |
| Virtual memory (Sv32 walk) | **Yes** | Already used | — | None | Keep |
| Memory protection (PTE R/W/X/U) | **Yes** | Fault path proven | — | None | Extend (guard pages) |
| Copy-on-Write | **No** | FORK correctness / density | Very high | PTE writable+fault handler | **Defer** (post page alloc) |

## Answers to decision questions

### 1. Keep AS structure and strengthen protection?

**Yes.** Retain 3 static AS slots and VA `0x108000` app model. Strengthen by: explicit region table, SPAWN/FORK PTE contract tests, optional **guard page** unmapped below stacks, scrub policy for FORK-exit slots.

### 2. Separate Memory Region manager?

**Yes, lightweight.** A documented (and eventually code) region registry listing PA/VA/owner/slot for code, stacks, PCB, pool, FB — used by SPAWN/scrub/WM checks. Not a full mmap subsystem in M25.2.

### 3. Heap allocator first?

**Not first.** First lock region ownership + FORK/SPAWN memory contract tests. Heap next if apps need it; otherwise window-pool bump for UI buffers may suffice short-term.

### 4. Page allocator necessary now?

**Not for M25.2.** Static slots work. Introduce guest or host page freelist when heap or COW needs frames beyond fixed tables.

### 5. FORK full copy vs COW?

**Near term:** document “PCB fork + slot AS” as intentional; either (a) **forbid/fail FORK** when target slot code PTE empty without image, or (b) **memcpy parent user code page** into child slot on FORK (simple full-page copy, not COW).  
**Long term:** COW after page allocator + write-fault — optional M25.x+, not M25.2.

### 6. Instrumentation?

| Metric | How (no ABI break) |
|--------|---------------------|
| Slot used / FREE / ZOMBIE | PCB scan in host tests (existing pattern) |
| Code PTE valid | `haeun_app_slot_user_pte` |
| Scrub effectiveness | memcmp zeros after reap (M15-style) |
| Stack high-water | optional watermark word in ustack page (test-only) |
| Leak of `runs[]` | `haeun_app_run_at` |

Do not claim heap leak freedom without tools.

## Recommended M25.x order

| Step | Focus | Deliverable |
|------|-------|-------------|
| **M25.2** | Region map + contract tests; FORK memory policy (copy page **or** explicit fail); scrub FORK slots on EXIT if no `runs[]` | docs + tests + minimal `app_env`/`proc_fork` fixes |
| **M25.3** | Stack guard PTE / overflow fault tests; slot0 scrub policy clarity | guest PT tweak + tests |
| **M25.4** | Optional guest bump heap in reserved VA **or** host-assisted buffer pool | additive ECALL only if needed |
| **M25.5+** | Page freelist; COW FORK exploration | large; separate proposal |

### Non-goals (near term)

- Growing NPROC/AS  
- Redesigning WM  
- Replacing Sv32  
- Claiming foundation `kernel/mm` is process-v1 MM  

---

## Minimal M25.2 success criteria

1. Written region ownership table matches code.  
2. FORK behavior is tested and matches documented policy.  
3. EXIT/fault leaves no readable stale app code in reusable slots 1–2 (including FORK-originated where policy requires scrub).  
4. `make test` green; M20–M24 preserved.  
5. No unjustified ISA break.
