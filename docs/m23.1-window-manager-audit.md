## Operation traces (entry → effect)

### Window create

1. Guest `ECALL WIN_CREATE` (18) → `haeun_gfx_ecall_io`  
2. Validates FB ready, backing RAM/align/FB exclusion/overlap; process pid≠0 also requires pool `[0x18000,0x100000)`  
3. `haeun_gfx_wm_create` → free slot ≤7, `used=1`, `z=next_z++`, `owner_pid=0`  
4. If pid≠0: `set_owner`, `EVT_CREATED`, `raise`, `set_focus`, `evt_on_focus`

### Window destroy

1. Guest `WIN_DESTROY` (19) with ownership check → optional `EVT_DESTROYED` → `wm_destroy` (clears `focus_id` if match) → `evt_sync_focus`  
2. Or process `EXIT` / fault → `ecall_mux` `reap_pid` → `evt_reap` + `app_reap`/`destroy_windows` → `evt_sync_focus`  
3. Or chrome CLOSE on **unowned** window → immediate `wm_destroy`  
4. Or chrome CLOSE on **owned** window → `EVT_CLOSE` only (guest must destroy / exit)

### Z-order

- `raise` assigns `z = next_z++`  
- `haeun_gfx_compose` sorts visible windows by ascending `z`, then blits  
- Click path (`hit_focus` / chrome) raises hit window before focusing

### Focus + keyboard

- `wm.focus_id` is sole keyboard target  
- `haeun_evt_route_key` → owner of `focus_id` queue (`evt.c`)  
- No focus → key dropped (`[haeun-evt] key dropped`)  
- Viewer/`--input`: `chrome_key` → same route; may adopt topmost if focus empty

### Mouse

- With chrome: `haeun_gfx_chrome_pointer` zones (client/title/min/max/close/resize)  
- Shell (`w≥FBw && h≥FBh`): no host chrome paint; no drag; client mouse → evt  
- Without chrome: `hit_focus` on LMB (input host) or viewer hit path

### Geometry / visibility / redraw

- Move/resize/min/max/restore: **host WM API** (`gfx_wm*.c`) + chrome gestures  
- **No** guest `WIN_MOVE` / min / max syscalls in `sec.h` / `gfx_ecall.c`  
- Redraw: guest `GFX_COMPOSE` and/or viewer `chrome_present` (compose + host decorations)  
- No separate dirty-rect invalidation ABI; chrome sets `dirty` for viewer refresh

## Architecture risks

### W1 — Focus not transferred after minimize/close event

| Field | Detail |
|-------|--------|
| Location | `haeun_gfx_wm_minimize`; chrome `ZONE_CLOSE` for owned windows |
| Path | Minimize focused app → `focus_id=-1`; keys drop until click |
| Severity | **Low–Med** (UX) |
| Status | **Confirmed** behavior in source; unit tests expect focus ≠ minimized id |

### W2 — Owned chrome Close does not destroy

| Field | Detail |
|-------|--------|
| Location | `gfx_chrome_ptr.c` `ZONE_CLOSE` (`opid > 0` → `EVT_CLOSE` only) |
| Path | Click red chrome button on calc without guest CLOSE handler → window remains |
| Severity | **Med** if guest ignores CLOSE; current calc/edit/files **do** handle type 8 |
| Status | **Confirmed** by design; apps in tree handle it |

### W3 — Stale `evt.last_focus` if windows destroyed outside mux

| Field | Detail |
|-------|--------|
| Location | `haeun_app_destroy_windows` (no `evt_sync_focus`); mux `reap_pid` **does** sync after |
| Path | Calling destroy_windows alone without sync |
| Severity | **Low** |
| Status | **Potential** — production EXIT/fault path syncs; guest `WIN_DESTROY` syncs |

### W4 — Dual composition (guest + viewer)

| Field | Detail |
|-------|--------|
| Location | `shell_compose` + `haeun_viewer_refresh_fb` → `chrome_present` |
| Path | `--viewer` may compose twice per slice |
| Severity | **Info** (M22.4 R1) |
| Status | **Confirmed** intentional |

### W5 — Event to wrong application

| Field | Detail |
|-------|--------|
| Location | `haeun_evt_route_key` uses `wm->focus_id` only |
| Path | Shell still focused → digit `1` spawns; app focused → digit goes to calc |
| Severity | **Info** / expected |
| Status | **Confirmed** — not a bug; focus discipline required |

### W6 — Window table exhaustion

| Field | Detail |
|-------|--------|
| Location | `wm_create` max 8 |
| Path | Create 9th → `BAD_ARGUMENT` / guest −1 |
| Severity | **Low** (cap) |
| Status | **Confirmed**; exercised in fault/NOSPC style tests |

### W7 — Drag/resize without FB clamp

| Field | Detail |
|-------|--------|
| Location | chrome drag/resize |
| Path | Drag title off-screen; blit clips |
| Severity | **Low** |
| Status | **Confirmed** potential UX issue; compose clips pixels |

### W8 — No guest move/min/max ABI

| Field | Detail |
|-------|--------|
| Location | `sec.h` lacks move/min/max; only host chrome |
| Path | Headless `--input` without chrome cannot drag |
| Severity | **Med** for M23 product goals if guest-driven WM is required |
| Status | **Confirmed** architectural gap |

### W9 — Application exit while window registered

| Field | Detail |
|-------|--------|
| Location | `reap_pid` → destroy_windows |
| Path | Guest `EXIT` / halt after destroy in apps; mux reaps leftovers |
| Severity | **Low** if EXIT always used |
| Status | **Mitigated** in current mux; orphan risk only if process dies without EXIT assist |

### W10 — Z-order / focus corruption

| Field | Detail |
|-------|--------|
| Location | `next_z` uint32; destroy does not compact z |
| Path | Long raise sequences |
| Severity | **Info** |
| Status | **Unconfirmed** defect; ordering remains total while `next_z` advances |

No confirmed framebuffer corruption from WM tracing in this audit; M22.4 PPM gate remains green for shell restore.

## Existing capabilities (summary)

Host WM is a compact fixed-table compositor with ownership, focus, z-order, compose, and chrome-driven move/min/max/close. Guest process apps get create/destroy/fill/pixel/raise/text/query/fill_rect/compose + evt CLOSE/focus. Desktop shell is a fullscreen owned window that skips host chrome.

## Confirmed defects vs gaps

- **Defects (must-fix for correctness):** none newly confirmed as data corruption; CLOSE-without-handler is guest contract.  
- **Gaps for M23 product WM:** no guest move/min/max; weak focus recovery after minimize; dual compose; no guest multi-window integration suite beyond unit/chrome tests.
