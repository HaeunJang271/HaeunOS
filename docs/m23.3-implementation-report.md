# M23.3 Implementation Report — Window State & Input Routing

Date: 2026-11-16  
Constraint: HAEUN-32 ISA/ABI unchanged; no guest move/min/max; no desktop redesign.

## Audit findings

| Area | Finding | Fix |
|------|---------|-----|
| `set_focus` | Allowed minimized/invisible targets | Reject ineligible ids |
| `route_key` / mouse / wheel | Delivered to stale min/hidden `focus_id` | Require eligible focus |
| `chrome_key` | Adopted topmost only when `focus_id < 0` | Recover when focus ineligible |
| `haeun_gfx_compose` | Ordered by `used&&visible` only | Also skip `minimized` |
| `set_visible(1)` | Could leave `minimized=1` | Clear minimized on show |
| Minimize/destroy | Already recover focus (M23.2) | Unchanged |
| Owner exit | `destroy_windows` + recover | Covered by stress tests |
| Hit-test / recover | Fullscreen unowned shell stole clicks/focus from lower-z apps | Prefer non-shell / `owner_pid>0` |

Valid focused window: `used && visible && !minimized`.

## Test coverage

- **State**: create/show/hide/min/restore/raise/focus/destroy; owner multi-window exit; capacity 8 + stress; key drop on stale focus.
- **Input routing**: concurrent calc+edit; A/B keys follow focused pid; minimize removes calc from eligibility.
- **Redraw**: host compose pixels after raise/min; guest multiwin PPM green-on-top; desktop raise/min dump.
- **Stress**: create/destroy loops; guest `app_win_cap` / `app_multiwin`; fault cleanup remains M17.

## Limitations

- Physical HID not claimed (`--input-script` only).
- Dual compose (guest vs viewer `chrome_present`) unchanged.
- No guest min/max/move ABI.
- Desktop strip restore-of-minimized not automated beyond chrome min + focus recover.
