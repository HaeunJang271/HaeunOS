# M25.5 FORK × Heap Policy

Date: 2026-11-16  
Current FORK (no heap): copies **code** + **ustack**, relocates SP; no COW  
([m25.3-fork-memory-contract.md](m25.3-fork-memory-contract.md)).

## Constraint

Any heap policy must **not** break:

- Child `r1=0` / parent `r1=pid` ABI  
- Code + ustack clone semantics  
- AS×3 and READY-after-clone  
- M25.4 stack guards  

## Options

### 1. Full heap page copy (recommended if heap ships)

On FORK, after ustack copy: `memcpy` parent heap PA → child heap PA (fixed size); child heap PTE already points at child PA (boot/SPAWN).  
Pointers inside the heap remain valid (shared VA model).  
Matches “child clones parent private memory” for the new region.

### 2. Empty child heap (wipe)

Zero child heap on FORK; do not copy.  
**Breaks** snapshot expectations for heap-backed data; only acceptable if documented as “heap not part of FORK image” and apps treat heap as non-inherited — weaker than M25.3 spirit.

### 3. Leave heap unsupported under FORK

Ship malloc only for SPAWN apps that never FORK, or fail FORK if heap dirty — **hostile** to M17/M24 FORK callers if FORK starts failing. Reject unless FORK remains success with options 1 or 2.

### 4. COW

**Out of scope** (milestone ban). Do not design PTE write-fault sharing for M25.6.

## Decision for M25.6 planning

| Phase | Policy |
|-------|--------|
| Until heap exists | N/A — no heap to inherit |
| When fixed heap is added | **Option 1: page-copy** heap with code/ustack |
| Deferred | Options 2–4 |

## EXIT / isolation

- Child EXIT scrubs **child** heap PA only (extend `scrub_slot`).  
- Parent heap untouched.  
- Parent EXIT similarly.  
- No shared heap PA between processes.

## Failure

If heap copy were to fault mid-way (should not if identity maps exist for heap PAs like foreign stacks): keep READY deferred until all copies finish; on failure free PCB (same discipline as M25.3). Pre-alloc slot full still returns `-1` with no partial child.
