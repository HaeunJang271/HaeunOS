# M21.3 Implementation Report — Persistent VM Runtime

Date: 2026-11-15  
Reference: `docs/m21.2-stop-cause-investigation.md`

## Problem

Interactive `--persist --viewer` stopped after ~10M host steps (`HAEUN_VM_STEP_LIMIT` / result 6) while the guest desktop idle loop was still healthy. `DestroyWindow` followed the host stop.

## Architecture (Phase 1)

| Concern | Mechanism |
|---|---|
| Per-frame / per-pump quantum | Unchanged `VIEW_SLICE` (256) inside `haeun_vm_viewer_run` |
| Cumulative accounting | `steps_executed` still counted; halt line prints total |
| Explicit guest shutdown | `HAEUN_VM_HALTED` (Esc → `EXIT(0)`) unchanged |
| Actual VM faults | Non-`OK` / non-`HALTED` step results still abort the run |
| Viewer shutdown | `plat.quit` / `DestroyWindow` on run end unchanged |
| Cumulative ceiling | **Non-persist:** `INSTRUCTION_BUDGET` (10M). **Persist:** `UINT64_MAX` unless `--max-steps N` |

`STEP_LIMIT` is **not** ignored: if a ceiling is configured and reached, the host still returns `HAEUN_VM_STEP_LIMIT` and prints a dedicated diagnostic. Persist mode simply does not install the historic 10M ceiling by default.

## Changes

| File | Change |
|---|---|
| `src/main.c` | Persist → unbounded `run_budget`; `--max-steps N`; `--persist-stress`; clearer STEP_LIMIT log |
| `src/vm_input_host.c` / `.h` | `haeun_vm_input_host_load_m21_stress_script` (events after 10M + Esc) |
| `tests/m21_3_persistent_runtime_tests.py` | Automated acceptance |
| `Makefile` | Hook m21.3 test |

No ABI / ISA / guest `desktop.s` changes.

## CLI

```text
--persist              long-running desktop; default run_budget = UINT64_MAX
--persist-stress       load post-10M input script (implies --persist)
--max-steps N          explicit cumulative ceiling (any mode)
```

## Test map

1. Survive past 10M (`--persist-stress --input --max-steps 12000000`)
2–4. Viewer quanta implied by continued stepping; keyboard after 10.5M; mouse in stress script
5. Esc → `r1=0` halt
6. Fault image still `guest halted`; `--persist --max-steps 50000` still STEP_LIMIT
7. Non-persist ceiling / M20 launcher retained

## Results

### Automated

- `tests/m21_3_persistent_runtime_tests.py`: **PASS**
- Full `make clean && make all && make test`: **PASS** (exit 0), including m21 + m21.3 hooks

### Scripted runtime

```text
.\build\haeun-vm.exe .\build\process_desktop.hxf --apps --persist --persist-stress --input --max-steps 12000000
→ guest halted after 11001114 instructions; r1=0x00000000
→ key sc=0x02 and Esc after the historic 10M threshold
```

```text
.\build\haeun-vm.exe .\build\process_desktop.hxf --apps --persist --viewer --max-steps 12000000
→ viewer: frames=46876 ( > prior ~39064 at 10M )
→ STEP_LIMIT at exactly 12000000 (ceiling honored; not ignored)
```

### Interactive viewer

- Unbounded `--persist --viewer` (no `--max-steps`): supported by `run_budget=UINT64_MAX`; human Esc/HID session **not** claimed here as physical HID PASS.
- Agent proxy: viewer remained active through 12M cumulative steps (above).
