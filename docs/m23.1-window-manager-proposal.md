# M23.1 → M23 Window Manager Proposal

Date: 2026-11-16  
Companion: [m23.1-window-manager-audit.md](m23.1-window-manager-audit.md)  
Constraint: preserve HAEUN-32 ISA, existing ABI numbers, guest apps, 320×180 FB, M22 desktop shell, current VM model. **No new graphics framework.**

## Design stance

Treat the current `haeun_gfx_wm` + `gfx_chrome` + `evt` stack as the M23 WM. Extend **minimally** where the audit found product gaps; do not rewrite compose or replace the 8-slot table unless a measured defect forces it.

```
Guest apps / desktop
        │ ECALL (existing 18–23, 27–28, 37, 51)
        ▼
┌───────────────────┐     ┌─────────────┐
│ gfx_ecall / m20   │────▶│ evt hub     │
└─────────┬─────────┘     └──────▲──────┘
          ▼                      │
┌───────────────────┐     ┌──────┴──────┐
│ haeun_gfx_wm      │◀────│ gfx_chrome  │◀── viewer / input-host
│ (table, z, focus) │     │ (gestures)  │
└─────────┬─────────┘     └─────────────┘
          ▼
┌───────────────────┐
│ haeun_gfx_compose │──▶ primary FB 320×180
└───────────────────┘
```

## Essential changes (M23.2+)

Ordered by dependency. Each item must keep ABI IDs stable; new ECALL numbers only if absolutely required and appended after `HAEUN_SYS_MAX`.

### E1 — Focus recovery policy (host-only first)

**Problem:** Minimize / owned-close path can leave `focus_id == -1` (W1).  
**Minimal fix:** After minimize or destroy, optionally focus topmost remaining visible non-shell window (or shell). Prefer implementing in chrome/`wm_minimize`/`wm_destroy` helpers shared by both paths.  
**ABI:** unchanged.  
**Apps:** unchanged.

### E2 — Guest-level multi-window integration tests

**Problem:** Capability exists but M22 desktop only proves one floating app + shell.  
**Add:** Guest or host-driven process tests: two app windows, click/raise focus, close focused vs background, reopen, compose PPM z-order samples.  
**ABI:** unchanged.

### E3 — Document + optionally unify CLOSE semantics

**Problem:** Chrome close is soft for owned windows (W2).  
**Minimal:** Keep soft CLOSE (apps already handle). Add explicit guest test that chrome CLOSE delivers `EVT_CLOSE` and app exits.  
**Optional later:** host timeout destroy — **not** essential.

### E4 — Compose ownership note / single present under viewer

**Problem:** Dual compose (W4).  
**Minimal:** Documentation + optional guest skip of `GFX_COMPOSE` when viewer attached is **hard** without ABI/host flag. Prefer: keep both; ensure chrome_present remains authoritative under `--viewer` (status quo from M22.4). Only change code if a measured double-clear bug appears.

## Optional enhancements (defer unless product demands)

| ID | Idea | Why optional |
|----|------|--------------|
| O1 | Guest `WIN_MOVE` / min / max ECALLs | Chrome already covers interactive WM; needs new ABI numbers |
| O2 | Clamp drag/resize to FB | UX polish (W7) |
| O3 | Dirty-rect invalidate ECALL | Premature; full compose is fine at 320×180 |
| O4 | Raise-above / lower API | Raise-to-top suffices |
| O5 | Grow `MAX_WINDOWS` | Caps are intentional; change only with tests |
| O6 | Taskbar minimize list | UI redesign — out of M23 minimal scope |

## Explicit non-goals

- New retained-mode UI toolkit / scene graph  
- Changing FB to non-320×180  
- Rewriting desktop shell tiles into multiple WM windows  
- Claiming physical HID certification without manual evidence  
- Breaking calc/edit/files Esc/CLOSE behavior

## Testing strategy

### Host-side unit (extend existing)

| Test | Covers |
|------|--------|
| `gfx_wm_tests` | create/destroy, raise z-order, hit_focus, visible, fill_rect |
| `gfx_chrome_tests` | click focus, min/max/restore, unowned close destroy |
| `m20_window_tests` | evt CREATED/FOCUS/CLOSE/DESTROYED |
| **New** | focus recovery after minimize; destroy focused then key drop vs retarget |

### Guest-level integration (new M23.2 suite)

| Scenario | Observable |
|----------|------------|
| Two windows (e.g. calc then edit) | spawn logs; PPM shows both or topmost |
| Switch focus (scripted click) | `[haeun-evt] key pid=` changes |
| Correct z-order | raise then compose; top window pixels win |
| Close focused | CLOSE/EXIT; focus recovery; keys to remaining |
| Close non-focused | background destroy via CTRL/CLOSE; foreground keeps focus |
| Reopen app | second `spawn calc` after Esc |
| Redraw after state change | PPM after min/restore or close |
| Create/destroy loop | N cycles without fault / table leak |

Use `--input-script` (extend M22.3 style); **do not** count as physical HID.

### Physical HID

Manual checklist only (`docs/m22.4-manual-validation.md` pattern). Mark NOT TESTED unless operator fills PASS.

## Recommended M23.2 implementation order

1. **Focus recovery helper** + unit tests (E1)  
2. **Guest integration tests** for multi-window focus/z-order/close/reopen (E2)  
3. **Chrome CLOSE → app exit** guest assertion (E3)  
4. Re-run `make test`; update M22.4-style PPM artifacts if useful  
5. Only then consider O1 guest move/min/max ABI if demos require headless WM gestures

## Success criteria for M23.2

- Existing M20–M22 tests still green  
- New guest WM tests green  
- No ISA/ABI breakage for ECALL 18–23, 27–28, 37, 51  
- Calc/Edit/Files + desktop shell behavior preserved  
- Physical HID still explicitly separate from automation
