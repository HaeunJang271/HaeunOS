# M25.6 Implementation Proposal (from M25.5)

Date: 2026-11-16  
Nature: **proposal only**. M25.5 does not implement this.

## Go / no-go

| Path | Recommendation |
|------|----------------|
| Fixed 1×4 KiB user heap per AS slot + userland first-fit | **Go** for M25.6 if PA/VA chosen without `fill_k`/guard collisions |
| Dynamic brk/PMM/COW | **No-go** for M25.6 |
| Skip heap entirely | **Allowed** if placement audit during M25.6 kickoff finds no safe PA |

## Proposed layout (candidate — re-verify in M25.6)

> Numbers are **candidates** derived from unused holes in the audit; implementers must re-grep `proc_boot.s` / `app_env.c` and prove no PTE/PA owner before coding.

| Slot | Heap VA (shared) | Candidate heap PA | PTE |
|-----:|------------------|-------------------|-----|
| 0 | `0x00109000` | `0x0010E000` | U\|RW `0x17` |
| 1 | `0x00109000` | `0x0010F000` | U\|RW |
| 2 | `0x00109000` | `0x00110000` | U\|RW |

Rationale:

- VA `0x109000` is adjacent to code but **not** the RX code page; not in guard/stack band `0x112000`–`0x115000`.  
- PAs `0x10E`/`0x10F`/`0x110` are not current code (`108`/`10C`/`10D`) or stack PAs.  
- L0 index for VA `0x109` = `0x424` — must not clash with code PTE at `0x420`.

**Explicitly forbidden:** mapping heap onto guard VAs or shrinking stack below 4 KiB.

## PTE / boot / SPAWN changes (M25.6)

1. `map_slot*` / `fill_u`: install heap leaf U\|RW → slot PA.  
2. `fill_k`: add kernel identity RW (no U) for foreign heap PAs if FORK memcpy runs under parent AS (same pattern as ustack).  
3. `haeun_app_spawn`: wipe heap PA; do not leave stale allocator metadata.  
4. `scrub_slot`: zero heap PA (slots ≥1); decide whether to clear heap PTE (optional; boot remaps).  
5. Slot0: map heap for init if init should malloc; scrub still never destroys slot0 without policy change.

## Allocator

- Userland first-fit in the mapped page ([m25.5-allocator-design.md](m25.5-allocator-design.md)).  
- Link into apps that need it; process kernel need not interpret malloc.  
- **Prefer no new ECALL** in first cut. If kernel-mediated alloc is required later, propose additive syscall numbers in a dedicated ABI note before merging.

## FORK

- Extend `fork_user_mem` with heap page copy (policy option 1).  
- Do not copy guard pages.  
- Keep READY-after-full-clone.

## EXIT / reap

- Extend host scrub; guest fault/EXIT paths unchanged aside from larger wipe.  
- Tests: child free/malloc isolation; scrub zeros; reuse SPAWN.

## Test scope (M25.6)

| Area | Cases |
|------|-------|
| Layout | Heap PTE present; guard/stack/code unchanged |
| Allocator | malloc/free/calloc/realloc; OOM; double-free detect; overflow |
| Isolation | Two slots; writes do not cross PA |
| FORK | Heap snapshot + independence after mutate |
| Lifecycle | EXIT scrub; SPAWN reuse; fault kill |
| Regression | M25.2–M25.4, M17, M24 |

## ABI compatibility

| Change | Impact |
|--------|--------|
| New userland `malloc` symbols | None for existing apps that do not link them |
| New ECALL | **Avoid** initially; if added, additive only |
| FORK copies extra page | Behavior extension; still success path — existing callers OK if heap starts zeroed |
| Stack/guard | Must remain bitwise compatible with M25.4 tests |

## Risks

1. Identity-map pressure in `fill_k` (slot2 already special-cases `0x114000`).  
2. Accidental U mapping on a guard VA.  
3. Allocator metadata in a page that FORK copies — OK if intentional.  
4. Scope creep into multi-page dynamic heap.

## Suggested M25.6 phasing

1. Lock VA/PA table with a failing-closed audit test (PTE readbacks).  
2. Map + scrub + FORK copy (empty arena).  
3. Userland allocator + unit tests.  
4. Guest integration + full `make test`.
