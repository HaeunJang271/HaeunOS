# M24.4 Process Lifecycle Stress & Reclamation Audit

Date: 2026-11-16  
Scope: Phase 0 **read-only** code trace (no speculation).

## Path matrix

| Path | Entry | PCB | Parent/child | Host resources | PCB FREE |
|------|-------|-----|--------------|----------------|----------|
| 1 Normal EXIT | ECALL 0 → mux `reap_pid` → `sys_exit` | → ZOMBIE; `orphan_reparent`; `wake_wait` | children `ppid→PCB0.pid` | WM/evt/ipc/svc/fd/sock/AS once | WAIT/TRYWAIT/SPAWN memset |
| 2 Fault | `on_fault` `reap_pid` → `sys_fault_exit` | ZOMBIE once (guard) | same reparent | same once | same |
| 3 Dup EXIT | already ZOMBIE → `sy_ex_sched` only | unchanged | no second reparent | second ECALL impossible while ZOMBIE (not runnable); fault 2nd: host reap idempotent | — |
| 4 WAIT | `sys_wait` | own ZOMBIE → FREE + clear fd[] | `ppid==self` only | none (already host-cleaned) | yes |
| 5 TRYWAIT | `sys_trywait` | same as WAIT or r1=-1 | same filter | none | yes if reaped |
| 6 Parent death | EXIT/fault + `orphan_reparent` | parent ZOMBIE | live/ZOMBIE kids → init pid | parent resources only | kids unreaped until init WAIT/TRYWAIT |
| 7 Init TRYWAIT | desktop idle / tests | init reaps `ppid==init` | PCB0.pid | none | yes |
| 8 SPAWN memset | `haeun_app_spawn` | unused slot ZOMBIE → memset FREE | ignores ppid | runs[] already clear | yes (fallback) |
| 9 Slot reuse | SPAWN/FORK after FREE | new pid from `0xA404` | new ppid | scrub on prior reap | requires FREE PCB |

## Ownership timing

| Resource | Owner key | Cleared at | Idempotent? |
|----------|-----------|------------|-------------|
| Windows | `owner_pid` | `haeun_app_destroy_windows` in `app_reap` / reap_pid | destroy unused → no-op |
| Evt queues | `owner_pid` | `haeun_evt_reap` | slot memset |
| IPC eps | `owner_pid` | `haeun_ipc_reap` | close owned |
| Svc names | `owner_pid` | `haeun_svc_reap` | drop |
| Proc FDs | owner | `haeun_proc_fds_close_by_owner` | free |
| Sockets | owner | `haeun_socks_close_by_owner` | close |
| AS/code/stack | `runs[].pid` | `scrub_slot` | second `app_reap` → NOENT |
| PCB fd[] | guest | WAIT/TRYWAIT | zeroed |
| PCB slot | guest | WAIT/TRYWAIT/SPAWN memset | FREE=0 |

**Note:** `reap_pid` returns early if `pid==0` (no PCB pid 0 in normal boot; init is typically pid 1).

## WAIT vs TRYWAIT

Both scan PCB 0..3 for `state==ZOMBIE && ppid==self`, reap **one**, clear fds. WAIT blocks if none; TRYWAIT returns `-1`. Neither reaps another parent's zombie. After FREE, second call cannot re-reap that PCB.

## Confirmed defect (fixed in M24.4)

`haeun_sec_dispatch` switch lacked `HAEUN_SYS_TRYWAIT`; numbers ≤`SYS_MAX` still hit `default` → DENIED → poisoned `-1`. Guest `sys_trywait` never ran under the host VM. Fix: add `case HAEUN_SYS_TRYWAIT`.
