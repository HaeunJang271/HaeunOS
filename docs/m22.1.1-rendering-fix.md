# M22.1.1 Desktop Rendering Fix

> **HISTORICAL (M22.2):** Pre-M22.1.3 **64×32** shell notes. Current runtime is **320×180** — [m22.1.3-target-desktop.md](m22.1.3-target-desktop.md), [graphics-api.md](graphics-api.md).

## Symptoms (pre-fix)

Viewer / chrome-present screenshots showed:

1. Host window chrome (title bar + traffic-light buttons) drawn over the guest shell.
2. Shell window placed at `(0,6)` size `64×26`, leaving a title band that looked like a second overlapping window.
3. 8×8 font glyphs (brand / icons / taskbar labels) appearing as huge pixel blocks at viewer scale 8.
4. Large dark regions that looked “black” (compose clear / chrome letterbox / dark guest fill).
5. App windows (when spawned) overlapping the non-fullscreen shell by design of their fixed origins.

## Root cause (confirmed)

| Layer | Finding |
|---|---|
| Guest shell | `WIN_CREATE` used `(0,6) 64×26` so host chrome title (`TITLE_H=6`) occupied screen `y=0..5`. |
| Host chrome | `paint_one` always decorated every visible window, including the desktop shell. |
| Viewer vs dump | Win32 viewer calls `chrome_present` each frame; `--fb-dump` records the guest compose buffer. Idle bug was visible in the viewer because host chrome over-painted the shell. |
| Text | `WIN_DRAW_TEXT` uses an 8×8 font; at 64×32 + scale 8, glyphs dominate tiles. |
| Clear color | Guest `GFX_COMPOSE` often left `r2` unset; `shell_compose` now always loads desktop RGBA. |

Not a multi-process FB race: idle frame is shell PCB0 + host chrome overlay. Apps are separate windows on the same WM when spawned.

## Fix (smallest)

1. **Fullscreen shell** — `userland/desktop.s`: create `(0,0) 64×32`.
2. **Skip host chrome on fullscreen shell** — `src/gfx_chrome.c` `paint_one`: if `x<=0 && y<=0 && w>=64 && h>=32`, return.
3. **Compose helper** — `userland/desktop_draw.s` `shell_compose` loads clear `0x00101828` then ECALL 23.
4. **Compact chrome paint** — brand / status / icons / menu use small rect marks instead of 8×8 letter glyphs; taskbar at `y=25`.

## Residual limits (not redesigned)

- FB remains 64×32; viewer scale 8 still blocky by design.
- Spawned apps keep their own chrome and may overlap the shell (expected WM behavior).
- Glyph API unchanged; shell simply avoids large letter labels for now.
