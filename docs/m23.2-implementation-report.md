## Exact focus recovery behavior

Eligible window: `used && visible && !minimized`.

1. **Minimize** (`haeun_gfx_wm_minimize`): mark minimized/invisible, then `focus_recover`.
2. **Destroy** (`haeun_gfx_wm_destroy`): clear slot, then `focus_recover`.
3. **Hide** (`haeun_gfx_wm_set_visible(..., 0)`): then `focus_recover`.
4. **`haeun_gfx_wm_focus_recover`**: if current `focus_id` is still eligible, keep it; else set `focus_id` to topmost eligible by **z-order** (`haeun_gfx_wm_top_eligible`), or **-1** (documented no-focus) when none remain.
5. **`haeun_evt_sync_focus`**: if `focus_id` is ineligible (destroyed/min/invisible), clears to -1; then emits FOCUS/BLUR. Retargeting is owned by WM mutation paths so unit tests need not link the full WM object file twice.

Invariants:

- Focus never remains on a destroyed slot.
- Focus never targets a minimized or invisible window.
- Z-order is unchanged by recovery (only `focus_id` retargets).

## Guest-level coverage

- One guest creates two windows (`app_multiwin`): distinct ids, independent fill, raise changes focus flags via `WIN_QUERY`, destroy one leaves the other, recreate does not treat stale id as live, final compose PPM shows raised window on top.
- Capacity guest (`app_win_cap`): fills until table full (or 8), destroys, recreates, loops create/destroy.
- CLOSE-only guest (`app_close_life`): ignores Esc; exits only on type 8.
- Desktop scripts exercise chrome Close and minimize with real input-host + chrome path.

## CLOSE event and exit lifecycle

| Stage | Mechanism | Verified by |
|-------|-----------|-------------|
| CLOSE delivery | Chrome `ZONE_CLOSE` → `haeun_evt_win_post(..., EVT_CLOSE)` for owned windows (soft; slot kept) | `app_close_life` + `chrome-close-app` |
| Guest handle / exit | Guest polls type 8 → `EXIT` | Same guest exit code 0 |
| Host reap | `reap_pid` → destroy owned windows → `evt_sync_focus` | Desktop `chrome-close-calc` then Esc shutdown |
| Focus recovery | Recover after destroy on reap | `focus_id` in input-host summary; unit tests |
| Shell alive | Desktop continues until Esc | Persist desktop completes halt after Esc |

Owned chrome Close ≠ destroy ≠ exit. Unowned chrome Close still destroys immediately (unchanged).

## Window capacity and cleanup

- `HAEUN_GFX_WM_MAX_WINDOWS == 8` unchanged.
- Desktop root+strip consume two slots; guest fills remaining until create fails.
- Destroy frees a slot; subsequent create succeeds.
- Stress loop reuses backing without leaving used orphans or focus on destroyed ids.

## Remaining limitations

- No guest ABI for move/minimize/maximize (chrome-only gestures).
- Physical HID not claimed; scripts are synthetic.
- Dual compose (guest `GFX_COMPOSE` + viewer `chrome_present`) unchanged (M23.1 W4).
- Soft CLOSE has no host timeout-destroy (deferred).
