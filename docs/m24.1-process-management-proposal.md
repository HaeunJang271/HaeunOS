# M24.1 → M24 Process Management Proposal

Date: 2026-11-16  
Companion: [m24.1-process-management-audit.md](m24.1-process-management-audit.md)  
Constraint: preserve HAEUN-32 ISA, existing ABI numbers unless a proven defect forces an additive change, desktop + WM v1, guest apps, current VM model.

## Design stance

Treat **guest process-v1** (PCB/RR/WAIT/ZOMBIE) and **host app_env/mux reap** as one product lifecycle with two stages:

1. **Resource stage (host):** windows, evt, ipc, fds, socks, AS scrub.  
2. **PCB stage (guest):** ZOMBIE → FREE via WAIT (or documented orphan reclaim).

M24 should make that contract **explicit, tested, and leak-free under stress**—not replace the scheduler or invent a new process API surface.

```
APP_SPAWN / FORK
      │
      ▼
   READY ──► RUNNING ──► EXIT/fault
                │              │
                │              ├─ host reap_pid (resources)
                │              └─ guest ZOMBIE
                ▼
              WAIT ◄──────── wake_wait
                │
                └─► child FREE (PCB reaped)
```

## Essential changes (M24.2+)

Ordered by dependency. Prefer host+guest tests over new ECALLs.

### E1 — Documented dual-stage EXIT contract + tests

**Problem:** Operators confuse “host cleaned” with “PCB FREE”.  
**Minimal fix:** Spec + tests asserting: after EXIT, WM/evt/ipc gone **and** PCB is ZOMBIE until WAIT/orphan reclaim.  
**ABI:** unchanged.

### E2 — Reliable WAIT/EXIT pairing for app/desktop path

**Problem:** Desktop apps often EXIT without parent WAIT; orphan ZOMBIE relies on next SPAWN memset.  
**Minimal fix (pick one, test hard):**  
- (Preferred) Desktop/init periodically WAIT or explicit reap helper that FREEs orphan ZOMBIEs without requiring a new spawn; **or**  
- Keep SPAWN-time reclaim but add stress tests that prove bounded zombie count.  
**ABI:** prefer no new numbers; if a host-only reclaim assist is required, append after `HAEUN_SYS_MAX` only with proof.

### E3 — Parent death / orphan policy

**Problem:** No reparent; children keep dead `ppid`.  
**Minimal fix:** On parent EXIT, either reparent live children to init (pid of slot 0) **or** document “orphans remain until SPAWN reclaim” and test both live and zombie orphans.  
**ABI:** unchanged if guest-only PCB updates.

### E4 — Slot accounting clarity (NPROC vs AS)

**Problem:** 4 PCB vs 3 AS; FORK capped at 3.  
**Minimal fix:** Single source-of-truth constants + tests that FORK/SPAWN fail cleanly at capacity; reject use of PCB3 for runnable processes.  
**ABI:** unchanged.

### E5 — Fault + multi-resource stress

**Problem:** Coverage exists (M17) but not combined with multi-window/IPC ownership.  
**Minimal fix:** Guest fault while owning windows + IPC; assert host reap + parent WAIT; no scheduler hang.  
**ABI:** unchanged.

### E6 — Idempotent EXIT / double-reap hardening

**Problem:** `sys_exit` lacks ZOMBIE guard (fault path has one).  
**Minimal fix:** Mirror fault_exit guard; host reap already mostly idempotent—add tests.  
**ABI:** unchanged.

## Optional (defer)

| ID | Idea | Why optional |
|----|------|--------------|
| O1 | Selective `WAIT(pid)` | Field exists; apps don’t need it yet |
| O2 | Grow AS slots / NPROC | Product demand only |
| O3 | Copy-on-write FORK memory | Large MMU project |
| O4 | Priority scheduler | RR sufficient |
| O5 | Host process debugger API | Out of scope |

## Explicit non-goals

- New ISA  
- Breaking ECALL 0–10 or APP_SPAWN 26  
- Rewriting WM or desktop shell  
- Claiming physical HID  
- Host-thread “real” multiprocessing  

## Recommended M24.2 implementation order

1. **E1** contract tests (EXIT → resources gone, PCB ZOMBIE).  
2. **E6** idempotent EXIT.  
3. **E2** orphan/WAIT policy + stress (bounded zombies).  
4. **E3** parent-death policy (reparent **or** documented reclaim).  
5. **E4** capacity matrix tests (FORK/SPAWN/NOSPC).  
6. **E5** fault × windows × IPC integration.  
7. `make test` green; update `process-v1.md` to match dual-stage reality.

## Success criteria for M24.2

- EXIT/WAIT/orphan behavior matches written contract  
- No zombie unbounded growth under desktop SPAWN/EXIT loops  
- Multi-window + IPC cleaned on EXIT/fault  
- Existing M20–M23 regression green  
- No unjustified ABI breaks  

## Test strategy (M24.2)

| Layer | Cases |
|-------|-------|
| Guest unit / image | FORK+WAIT, fault+WAIT (extend M17), double EXIT |
| Host unit | app_reap idempotency, scrub PTE, NOSPC |
| Integration | Desktop repeated launch/exit; zombie PCB count probe |
| Stress | SPAWN/EXIT loops; FORK to AS cap; EXIT with 2 windows + IPC |

## Relationship to Window Manager v1

WM ownership (`owner_pid`) and focus recovery (M23) are **consumers** of process EXIT. M24 must not regress `haeun_app_destroy_windows` / `evt_sync_focus` on `reap_pid`. Process work stays in PCB/SPAWN/WAIT; WM stays in gfx/evt.
